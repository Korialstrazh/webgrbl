# UI Components

The design tokens, the antd components and the antd theme that gives them our look, the few views that stay custom in `src/views/`, and the overlay registry that tells the Escape-to-STOP hotkey whether the user is in the main view or inside an overlay.

## Key Takeaways

- **Tokens.** `src/styles/tokens.scss` defines every colour, radius (6 / 8 / 10 / 14 px, written in rem), spacing step, font family and the 2.75 rem machine-control target (`--target-min`) as CSS custom properties on `:root`. Our SCSS uses `var(--...)` only. Text contrast is held at 4.5:1 or better, checked by `tokens.contrast.test.ts`; danger buttons use `--color-danger-button` (with hover and active steps) because the plain danger colour is too light under light text. Error text uses the lighter `--color-danger-text` (#ff6b6b, at least 5.41:1 on the background and every surface). `--color-focus-ring`, `--focus-outline-width` and `--focus-outline-offset` make up the keyboard focus outline of our own controls. Fonts (Inter, JetBrains Mono) are self-hosted in `src/styles/fonts/`.
- **antd for controls.** Buttons, switches, checkboxes, text inputs, segmented selectors, selects, sliders and popovers are antd components (`Button`, `Switch`, `Checkbox`, `Input`, `Segmented`, `Select`, `Slider`, `Popover`), used directly in the containers; dialogs and drawers are antd `Modal` and `Drawer`, used only through `BedRegionModal` and `BedRegionDrawer` (see below). antd prop values (sizes, types, triggers, placements) come from `src/utils/antd.constants.ts`. Mapping of the former self-built views:
  - text buttons: antd `Button` (default type for the bordered button, `type="primary"` for the main action, `type="text"` for menu-like actions); machine controls use `size="large"`;
  - icon-only buttons: antd `Button` with `icon` and an `aria-label` as the accessible name;
  - STOP: `type="primary"`, `danger`, `size="large"`, plus a `min-height: var(--target-min)` floor in `StopButton/styles.module.scss`;
  - toggles: antd `Switch` inside a `<label>` with visible text, which gives the switch (role `switch`) its accessible name;
  - checkboxes: antd `Checkbox` with its label as children (the console's status-reports checkbox); text inputs: antd `Input` with an `aria-label` (the console command input keeps Enter-submit and ArrowUp/Down history);
  - small actions inside a chip or toast: antd `Button size="small"` (the toast dismiss button, named by its `aria-label`);
  - selects: antd `Select` with an `id` and a `<label htmlFor>` (the label names its `input[role=combobox]`), `virtual={false}` for the short lists; sliders: antd `Slider` named by `ariaLabelledByForHandle` pointing at its visible label;
  - segmented selectors: antd `Segmented` with `aria-label` (a `radiogroup` of native radios sharing one name, so one tab stop; arrow keys move the selection and wrap, pinned by `src/utils/antd.upgrade.guard.segmented.test.tsx`).
- **Theme mapping.** `ANTD_THEME` (`src/utils/theme/antd.theme.ts`) uses the dark algorithm and takes every value from the tokens: global tokens (accent with hover and active, surfaces, border, text, status colours, danger-button shades as `colorError` / `colorErrorHover` / `colorErrorActive`, `--color-danger-text` as `colorErrorText` so antd error text stays readable while buttons keep #b52a2d, disabled text and background, radius 8, Inter as `fontFamily`, JetBrains Mono as `fontFamilyCode`, control height 36) and component tokens. The dark algorithm derives darker shades from the seed colours, so `Button` and `Switch` get the exact accent and danger values back as component tokens. `Button` also gets dark text on the accent (`primaryColor` = `--color-bg`), light text on danger (`dangerColor` = `--color-text`), the surface-2 default background with the surface hover and active steps, label weight 600 and `controlHeightLG` = 44 px (`--target-min`), so every large button is a full touch target. `Slider` gets the accent track and handle on a surface-3 rail, `Select` accent hover and active borders and a surface-3 selected option, and `Segmented` a surface-1 track, muted items and a surface-3 selected item. `antd.theme.test.ts` checks every value against `tokens.scss`.
- **What stays custom.** `Panel` (titled section with an optional header action; kept as our own view to keep the approved card look), `ComingSoon`, `BedView` (the bed drawn to scale as SVG, see [[app-shell]]) and `ConsoleEntryList`. All are Redux-free. The connection pill button is also still our own markup and styles.
- **ComingSoon.** Wraps one not-yet-built control, which the caller renders as a real antd control with `disabled` (no handler) and shown without an outline so it reads as a note: a `SoonTag` follows it, and the description is a tooltip below the control on a wrapper (a disabled button fires no pointer events) and hidden text in the tag. One tag per control; a disabled `Segmented` option takes `ComingSoon` as its label.
- **antd overlays and Escape.** antd closes the top-most open `Popover`, `Modal` or `Drawer` on Escape from a `keydown` listener on `window` in the bubble phase (IME composition ignored). `StopHotkey` listens on `window` in the capture phase, so it always runs first and still sees the overlay registered as open; then the overlay closes, its owner's `isOpen` turns false and the registration is removed. By default one press never both closes an overlay and stops the machine; the next Escape stops again. When the user turns on "Esc stops over panels too" (gear beside STOP), one press does both. A Select dropdown inside an overlay is closed first: rc-select closes it on Escape and stops the event, so the popover stays open until the next Escape (checked in Chrome). In tests antd's ids are all `test-id` (NODE_ENV=test), so its Escape stack forgets the popover once a dropdown closes; the StopHotkey test closes that popover by its anchor instead.
- **Focus.** `AppModal` traps focus like any antd modal and closes on Escape. `BedRegionModal` closes on Escape and returns focus on close but does not trap Tab (rc-dialog only locks focus when its wrap is `position: fixed`, and the wrapper makes it `absolute`), so STOP stays keyboard-reachable; `BedRegionDrawer` traps focus while open and returns it on close, with STOP still clickable with the mouse. antd `Popover` moves no focus, so `ConnectionPopover` does it: once the popover has opened (`afterOpenChange`) focus moves to its first enabled control (a button or an antd Select's `input[role=combobox]`; or the popover itself, `tabIndex=-1`) with `preventScroll`, and when it closes while focus is inside, focus returns to the pill through an `anchorRef` that `ConnectionPill` passes in. The ref, not the focused element at open time, is used because Safari and Firefox on macOS do not focus a clicked button. When a pointer opened the popover (a `pointerdown` on the anchor, cleared by a `keydown` on it) focus returns with `focusVisible: false`, so the pill draws no ring after a mouse-driven or Escape-driven close; opened from the keyboard it keeps the ring. The former `useOverlayFocus` hook is gone.
- **Editing dialogs are app-level.** The palette, machine profiles, open project and add material dialogs use `AppModal` (add material moved there so every dialog dims the whole window with one scrim) (`src/containers/AppModal/`): rendered into the page body with a full-window mask, centred, `width: min(maxWidth, 100vw - 2rem)` (`getAppModalWidth`), body scrolling inside `100dvh - 8rem`. Inside the bed region they were clipped by a narrow bed, with the close button and right-hand fields cut off. It takes the antd props minus the placement and size ones, plus `isOpen`, `overlayIdPrefix`, `maxWidth` and `onClose`, and registers as an overlay while open.
- **Small dialogs and drawers stay in the bed region.** STOP must stay visible and clickable while a confirmation or drawer is open, so features never use a raw antd `Modal` or `Drawer`; they use `BedRegionModal` (`src/containers/BedRegionModal/`) and `BedRegionDrawer` (`src/containers/BedRegionDrawer/`). Both take the antd props minus the placement ones, plus `isOpen`, `overlayIdPrefix` and `onClose`. They render into the bed region element (`getContainer`), which `BedPanel` hands to `AppRoute` through its `hostRef` and `AppRoute` shares through `BedRegionHostContext` (`src/utils/bed/bed.region.host.context.ts`); a `rootClassName` turns antd's window-fixed mask and wrapper into `position: absolute`, so mask and panel fill only the `position: relative` bed panel, which the regions container clips. They call `useOverlayRegistration` while shown and keep antd's Escape-to-close (Escape calls `onClose`). Until the bed region has mounted they render nothing rather than fall back to the whole window. While a left `BedRegionDrawer` is open it sets its width (`getBedRegionDrawerInset`) as `--bed-region-drawer-inset` (`BED_REGION_DRAWER_INSET_PROPERTY`) on the host; the bed reads it as `margin-inline-start` only through the `bed-region` container query on `.bedBody` (58 rem and wider), so the drawer pushes the bed aside only when a strip about as wide as the drawer is left; in a narrower region (1440 px windows with default panels) it overlays the bed, which stays fitted to the whole region underneath. The earlier fixed 1280 px media query left a strip of about 300 px at 1440 px, which made the fitted bed a small square. `src/routes/AppRoute/index.overlays.test.tsx` checks, wide and narrow, that with either one open STOP sits outside the overlay root, the overlay root and its mask sit inside the bed region, STOP is enabled and its click dispatches `MachineStopRequested`, and Escape asks to close without stopping.
- **Overlay registry.** The `uiOverlay` slice (`ui.overlay.state.ts`) holds `openOverlayIds`. Dialogs and drawers register with `OVERLAY_KIND.DIALOG`; each one that opens raises `dialogOpenCount` and closes the connection popover, and the other popovers close through `usePopoverCloseOnDialogOpen`. `OverlayOpened` and `OverlayClosed` are idempotent per id; `selectIsAnyOverlayOpen` is true while any id is open. The STOP hotkey fires only when it is false.
- **Registration lives in containers.** `useOverlayRegistration(overlayIdPrefix, isOpen)` combines the prefix with React `useId()` into a unique id per mounted component (the registry is a set without reference counts, so a shared id would let one overlay's close hide another still-open one), dispatches opened/closed in an effect and closes on unmount. Every container that owns an antd `Popover` calls it with the same `isOpen` it passes to the overlay's `open`; `BedRegionModal` and `BedRegionDrawer` call it themselves.
- **Tests.** jsdom has no `ResizeObserver` (`vitest.setup.ts` installs a silent one from `resize.observer.mock.ts`) and never fires animation end events, so tests that open antd overlays render inside `AntdTestProvider` (`src/utils/test.support/antd.test.provider.tsx`: the app theme with `motion: false`); otherwise an overlay takes a full second to finish opening or closing.

- **Tooltip dismissal.** `TooltipDismissal` (mounted in `AppRoute`) calls `dismissHoverTooltips` on a window resize, a window blur and a bed view change: it sends a `mouseout` with no related target to the innermost `:hover` element, so React fires every hovered trigger's mouse leave and no hover tooltip stays floating where a moved control used to be. A main `CaptionedActionButton` (no label tooltip, such as Start) opens its blocked reason to the left, so it never covers the Frame and Export buttons below it.
