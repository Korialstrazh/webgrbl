# Projects and SVG import

A project is the design on the bed: a list of SVG objects with a size, position and rotation in machine millimetres (X right, Y up, origin front-left). It lives in the `projectDocument` slice with a snapshot undo history, the selection lives in `projectSelection`, and `SvgFilesImportRequested` turns picked or dropped files into objects through the sanitiser. The `project` slice and `project.saga.ts` store the open project in IndexedDB (Dexie) with autosave, and read and write `.webgrbl.json` files. User view: `docs/howto/projects-and-svg-import.md`.

## Key Takeaways

- **Document.** `ProjectObject` holds `id`, `name`, `svgText` (sanitised), `intrinsicWidthMm` / `intrinsicHeightMm` (size as imported), `xMm`, `yMm`, `widthMm`, `heightMm` and `rotationDeg`. `newProjectObject(overrides)` is the factory (also used by tests). `ProjectDocument` is `{objects, layers}`; the layers are described in [[layers-and-gcode]]. Limits and steps are in `project.constants.ts` (`MAX_PROJECT_OBJECTS` 50, `IMPORT_PLACEMENT_OFFSET_MM` 10, `MAX_UNDO_STEPS` 100, size bounds).
- **Slice `projectDocument`.** State is `{document, past, future}`. Actions: `ProjectObjectsAdded {objects}`, `ProjectObjectsTransformed {transforms}`, `ProjectObjectsDeleted {objectIds}`, `ProjectUndoRequested`, `ProjectRedoRequested`, `ProjectDocumentLoaded {document}` (replaces the document and clears the history). Selectors: `selectProjectDocument`, `selectProjectObjects`, `selectCanUndo`, `selectCanRedo`.
- **History.** Every change pushes the previous document on `past` (capped at `MAX_UNDO_STEPS`) and clears `future`. A change that changes nothing (no objects added, an unchanged transform, deleting unknown ids) records no step. One action is one undo step, so an import of several files is one step.
- **Selection.** `projectSelection` holds `selectedObjectIds`, set by `ProjectSelectionChanged {objectIds}`; ids of objects that leave the document are dropped from it.
- **Import saga `importSvgFiles`.** `SvgFilesImportRequested {files}` waits in the project command queue (see Command queue), so an import never lands in a document that a project switch is replacing, and one sent at start waits for the first project. It handles the files in order: a file over `MAX_SVG_FILE_BYTES` (by `File.size`, checked before reading) is rejected; otherwise `readSvgFile` reads `file.text()` and runs `getSanitizedSvg`. A failed read counts as not-svg and its error text is never shown.
- **Placement and names.** After the reads, the saga selects the objects again and places accepted object `i` of the request at `((existingCount + i) mod 10) * 10` mm on X and Y (`IMPORT_PLACEMENT_OFFSET_MM`, `IMPORT_PLACEMENT_CASCADE_LENGTH`), so the first import starts at 0,0 and later imports continue the cascade instead of landing on top. Objects are named after the file without its extension, with a `crypto.randomUUID()` id, scale 1 (width and height equal the intrinsic size) and rotation 0. All accepted objects go out in ONE `ProjectObjectsAdded`, then `ProjectSelectionChanged` selects them. Nothing is dispatched when no file was accepted. The same file imported twice gives two objects with different ids.
- **Limit.** The saga reads files asynchronously, so the count can change while it reads (a delete, undo or nudge from the bed). The count is therefore checked again right before the add: the accepted files are trimmed to the remaining room of 50 objects, and one error toast `TOAST_SVG_IMPORT_LIMIT_REACHED {limit}` shows if any file was trimmed or skipped.
- **Toasts.** Failure: error toast with `{fileName}` and one key per reason, mapped from `SVG_IMPORT_ERROR_KIND` by `SVG_IMPORT_FAILURE_TOAST_KEY` (`TOAST_SVG_IMPORT_FAILED_NOT_SVG`, `_NO_SIZE`, `_TOO_LARGE`); the other files still import. Content removed by the sanitiser: warning `TOAST_SVG_CONTENT_REMOVED {fileName}`. An object wider or taller than the bed (`getBedDimensions` over `selectGrblSettings`, `selectIsConnected` and `selectActiveMachineProfile`, as `BedPanel` does): info `TOAST_SVG_LARGER_THAN_BED {fileName}`. Toast texts never contain parser or error text.
- **Sanitiser.** `getSanitizedSvg(text)` returns `SanitizedSvg {svgText, widthMm, heightMm, removedContentKinds}` or `SvgImportFailure {errorKind}` (`not-svg`, `no-size`, `too-large`); `isSvgImportFailure` tells them apart. It parses with `DOMParser` as `image/svg+xml` and requires an `svg` root in the SVG namespace. It removes scripts, `on*` event attributes, `javascript:` and remote `href`s, remote or escaped CSS references (`url()`, `@import`, `image-set`), animation values that point to remote references, `foreignObject`, linked images (data images of png, jpeg, gif and webp are kept) and editor metadata. Removed visible content is reported once per kind (`foreign-object`, `linked-image`, `style-url`); editor metadata is removed silently. The size comes from `width` and `height` (units mm, cm, in, pt, pc, px) or the `viewBox` (user units as px); no size is `no-size`. Its own length check is a character-count backstop; the byte check is the caller's.
- **Bed editing (Tasks 5-7).** `BedObjects` draws the objects on the bed with select, drag, scale, rotate and nudge; a drop of files on the bed (`useSvgFileDrop`) sends every dropped file in one `SvgFilesImportRequested`, so a file that is not an SVG gets the not-svg error toast instead of being ignored. `getNormalizedRotationDeg` (`src/utils/project/`) turns any angle into [0, 360) and is shared by the bed rotate gesture and the Objects section.
- **Objects section.** `ObjectsSection` (in `DesignPanel`) lists the objects: each row is an antd button (`aria-pressed` when selected, accent border) with the name, `W x H` in mono (one decimal) and, from `isObjectOutsideBed` with `useBedDimensions`, an "Outside the bed" note; a click dispatches `ProjectSelectionChanged([id])`, the delete button (`aria-label` names the object) dispatches `ProjectObjectsDeleted`. With no objects it shows a hint and `SvgImportButton`. With exactly one selected, `ObjectTransformFields` shows X, Y, Width, Height and Rotation as antd `InputNumber` plus a "Lock aspect ratio" switch (on by default, local state). Each field keeps a local draft and commits on blur or Enter as ONE `ProjectObjectsTransformed` (one undo step); an unchanged value commits nothing. The input runs with `changeOnBlur={false}` and every commit clears the draft, because antd reports the rounded display value (one decimal) as a change on blur and on Enter even when nothing was typed, and that would leave a draft that later moves an object; the fields are keyed by object id, so selecting another object never shows a leftover draft. `getObjectTransformWithField` clamps width and height to 0.1-5000 mm, scales the other side by the same factor while locked, and normalises rotation (400 gives 40, -30 gives 330).
- **Import button.** `SvgImportButton` is an antd Button that clicks a hidden `<input type="file" accept=".svg,image/svg+xml" multiple>`; on change it dispatches `SvgFilesImportRequested {files}` and resets the input value so the same file can be picked again. It is used in the top bar and in the empty Objects section.
- **Undo and redo UI.** The top bar undo and redo buttons are disabled from `selectCanUndo` / `selectCanRedo`. `HistoryHotkeys` (mounted in `AppRoute` next to `StopHotkey`) listens on window: Ctrl/Cmd+Z undoes, Ctrl/Cmd+Shift+Z and Ctrl/Cmd+Y redo; it matches `event.key` lowercased plus modifiers, calls `preventDefault` when it acts, and does nothing for a text-entry target, while an overlay is open (`selectIsAnyOverlayOpen`) or during IME composition (the shared `canShortcutAct` in `src/utils/browser/`, also used by the bed keys), or while a drag or handle gesture runs on the bed (`selectIsBedGestureActive` in `bed.gesture.state.ts`, set by `useBedGestureActivity` in `BedObjects`), because the gesture commits onto the document as it is when the pointer comes up.
- **Project state.** The `project` slice holds `projectId`, `projectName`, `saveStatus` (`saved` / `saving` / `unsaved`, `PROJECT_SAVE_STATUS`), `hasSaveFailed` and `projectSummaries`; actions: `ProjectOpened`, `ProjectRenamed`, `ProjectSaveStatusChanged`, `ProjectSaveFailed`, `ProjectSummariesLoaded` (reports from the saga) and the requests `NewProjectRequested`, `ProjectOpenRequested`, `ProjectRenameRequested`, `ProjectDeleteRequested`, `ProjectSaveRequested`, `ProjectAutosaveDue`, `ProjectSummariesRequested`, `ProjectFileExportRequested`, `ProjectFileImportRequested`.
- **Storage.** `webgrbl.database.ts` is the one Dexie instance, database `webgrbl`, schema v1 (`project.database.constants.ts`): `projects` (`id, updatedAt`; name, ISO UTC times and the objects' transforms without SVG text), `svgAssets` (`[projectId+objectId], projectId`; the sanitised SVG text) and `appState` (`key`; `lastOpenedProjectId`, and `panelSizes`, the workbench panel sizes as a JSON list of percentages). Only the repositories next to it touch it (domain facade rule): `PANEL_SIZES_REPOSITORY` (`panel.sizes.repository.ts`) reads and writes `panelSizes` (see [[app-shell]]), and `PROJECT_REPOSITORY` (`project.repository.ts`) everything else: `createProject`, `getProject` (joins rows; an object whose SVG row is missing is left out), `saveDocument`, `renameProject`, `deleteProject`, `listProjects` (newest first), `pruneAssets`, `getLastOpenedProjectId` and its setter. It validates names (1-100 characters, `InvalidProjectNameError`), owns timestamps, throws `ProjectNotFoundError` for writes to a missing project and lets storage errors reject. SVG rows are written once per object and never rewritten; a save never deletes them (undo can bring an object back), `pruneAssets` does, in `openLoadedProject` and, for the closed project, in `switchToLoadedProject` after the next project is on screen, where the history is empty or gone.
- **Command queue.** `watchProjects` (`project.saga.ts`) puts New, Open, Rename, Delete, Save, AutosaveDue, Summaries, the file export and import, and SVG imports into one `actionChannel` read by one loop, so a write never runs in the middle of another command. Each command catches its own errors: a rejected database call logs and shows the fixed toast `TOAST_PROJECT_STORAGE_FAILED`. At start it opens the last opened project, else stores the document on screen in a new project with the default name in the user's language. **Switching** (`switchToLoadedProject`): Open reads the requested project, New creates its project, and Open file creates and stores its project, all BEFORE the open project closes (a project that is gone closes nothing and refreshes the list). `closeOpenProject` then saves until nothing is pending and returns the closed project with the document saved last; nothing that waits on storage runs between that last save and `openLoadedProject`, so an edit lands either in the old project before its last save or in the new one, never in a document that is thrown away. The closed project's unused SVG rows are pruned afterwards against that document. If the save fails the project stays open and a project created for the switch is deleted again (`switchToCreatedProject`). Delete of the open project opens the most recently changed remaining one, or a new one. A project open in a second tab and deleted there: the next save gets `ProjectNotFoundError` and stores the document in a new project without a toast (`recoverDeletedProject`).
- **Autosave.** `watchProjectAutosave` only times: a document change (`ProjectObjectsAdded`, `Transformed`, `Deleted`, undo, redo, `LayerSettingsChanged`, `LayerToggled`, `LayersReordered`) sets `unsaved`; `ProjectAutosaveDue` is sent 1000 ms after the last change (`AUTOSAVE_DEBOUNCE_MS`), at the latest 3000 ms after the first (`AUTOSAVE_MAX_WAIT_MS`), and at once on `pagehide` or a hidden tab. The queue then saves (skipped when already `saved`); a change during a save leaves `unsaved`, so the next save follows. A failed save sets `hasSaveFailed`, shows `TOAST_PROJECT_SAVE_FAILED` once until a save works, keeps the changes on screen and is retried by the next change or flush.
- **Project file.** `getProjectFileText` writes `{format: "webgrbl-project", version: 2, name, objects, layers}` as 2-space JSON with fixed field order (`PROJECT_FILE_*` constants; `getProjectFileName` strips forbidden characters, falls back to `project`). `getImportedProjectFile(text, palette)` reads versions 1 and 2 and returns `{name, document}` or `undefined` for bad JSON, wrong format or an unknown version, a malformed layer (`isProjectLayer`), more than 50 objects, bad field types (`isProjectFile`, `isProjectObject`), an invalid name or any SVG that fails sanitising; it re-sanitises and re-measures every SVG, clamps width and height, normalises rotation, trims each object name and cuts it to `MAX_OBJECT_NAME_LENGTH` (100) characters, and gives every object a new id. Before reading, the import saga rejects a file over `MAX_PROJECT_FILE_BYTES` (`MAX_PROJECT_OBJECTS` x `MAX_SVG_FILE_BYTES` plus a 50 MB JSON overhead allowance) by `File.size`, so a huge file never freezes the tab. The import saga opens the result as a NEW project (new id, never overwrites); failure: error toast `TOAST_PROJECT_FILE_INVALID`, nothing changes.
- **Top bar UI.** `TopBar` has `ProjectNameButton` (click to edit, `ProjectRenameInput`; an invalid name is ignored), `ProjectMenu` (New, Open..., Save with Ctrl+S, Save as file, Open file... through `ProjectFileInput`, Export G-code, see [[layers-and-gcode]]), `AutosaveReadout` (Saved, Saving..., Not saved) and Undo/Redo. `SaveHotkey` (in `AppRoute`) saves on Ctrl/Cmd+S and blocks the browser dialog, also in text fields and with an overlay open, not during IME composition. `OpenProjectDialog` lists `projectSummaries` (name, change time via `getProjectChangedTimeText`, object count) with Open, Rename, a confirmed Delete, "open now" on the open project, and Open file....
- **Bed tools.** `BedPanel` keeps the active tool (Select or Move); `BedObjects` handles select, Shift-click, drag, handles, nudge (`NUDGE_STEP_MM` 1, Shift 10), Delete or Backspace, and with Move a drag from empty bed moves the whole selection. Rotation snaps by `ROTATION_SNAP_DEG` (15) with Shift.
- **Tests.** Sagas run against fake-indexeddb; `LIVE_STORE_TASK_REGISTRY` (`live.store.tasks.ts`) keeps every `newStore()` root task so teardown cancels them and no store writes to storage during the next test.
- **Test style.** The import saga tests run `newStore()` with real `File` objects and wait with `vi.waitFor` for the expected objects or toast; the sanitiser tests parse in jsdom.
