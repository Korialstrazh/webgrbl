# App Shell

The scaffold every feature builds on: entry point, Redux store with sagas, PWA service worker, and the top-level route.

## Key Takeaways

- **CRUV layout.** `src/containers` (components with logic), `src/routes` (one-off top-level pages), `src/utils` (infrastructure), `src/views` (pure presentational components that are not antd: `Panel`, `ComingSoon`, `BedView`, `ConsoleEntryList`). Controls are antd components used directly in containers; see [[ui-components]].
- **Redux with class actions.** Every action is a class extending `Action<TPayload>`; `classActionToPlainObjectMiddleware` runs first and turns instances into plain objects. Each state file holds its state, actions, reducer, sagas, and curried selectors in `#region` blocks.
- **GRBL slices.** `grblConnection` (status disconnected / connecting / connected / lost, granted ports, selected port, baud rate, firmware identity, RX buffer size, settings, build info), `machineStatus` (latest resolved status; cleared on disconnect), `grblConsole` (entries capped at 2,000, hidden status reports, command history of 100, app-added info and error lines by localisation key) and `toast` (identical open toasts merge into a repeat count; info toasts expire after 5 s). `machineProfile` holds the machine profiles and the active one (see [[machine-control]]). The slices hold only serialisable data.
- **Controller bridge.** `watchGrblController` (`grbl.controller.saga.ts`) owns the single `GrblController` in saga scope and turns requests into controller calls and controller events into actions and toasts; details in [[grbl-engine]] (Redux bridge). `newStore(dependencies?)` takes optional `GrblControllerSagaDependencies` for tests (simulated laser, in-memory storage) and defaults to the browser's, which work without Web Serial.
- **Connection UI.** `ConnectionPill` (top bar) shows a status dot and label (success connected, warning connecting, danger lost, muted disconnected), the firmware name and version when connected, the selected port label, an Online/Offline indicator and a "No Web Serial" indicator. The pill button is the anchor (child) of `ConnectionPopover`, an antd `Popover` with `trigger="click"` and `placement="bottomRight"` whose `open` / `onOpenChange` follow the pill's `isPopoverOpen` state: a click on the pill toggles it, a click outside or Escape closes it. The popover registers itself with `useOverlayRegistration(CONNECTION_POPOVER_OVERLAY_ID, isOpen)`, so Escape never reaches STOP while it is open, moves focus to its first enabled control once open, returns focus to the pill (through `anchorRef`) when it closes with focus inside, and destroys its content while hidden (`destroyOnHidden`). The popover has the port select (an antd `Select`: localized "Simulated laser" plus granted ports as `USB <vid>:<pid>` in 4-digit lowercase hex, "Serial port" when the ids are unknown), the "Choose port..." button, the baud select (an antd `Select`) and the Connect/Disconnect toggle (disabled while connecting). Without Web Serial only "Choose port..." is disabled and the popover shows the unsupported explanation; the simulated laser stays connectable. Port and baud selects are locked while connecting or connected.
- **Console UI.** `ConsolePanel` owns the input (Enter submits trimmed non-empty text; ArrowUp/ArrowDown walk `commandHistory` newest first, ArrowDown past the newest clears; disabled unless connected), the status-reports checkbox and the auto-scroll: the list follows new lines unless a scroll event left it more than 1 rem (converted through the root font size) above the bottom. `ConsoleEntryList` (view) renders entries with a `>`/`<` prefix, a time, a class per direction, `t()` for info/error lines (`messageKey` + `messageParameters`) and the `CONSOLE_REALTIME_<COMMAND>` label for realtime entries.
- **Route composition.** `AppRoute` is a five-region workbench: `TopBar` (title, project placeholder, `ComingSoon` menus, undo/redo and autosave readout, `AppUpdatePrompt`, `ConnectionPill`), `DesignPanel`, `BedPanel`, `MachinePanel` and `StatusStrip`. The workbench is an antd `Layout` that fills the window (`height: 100dvh; overflow: hidden`, so the page never scrolls): `TopBar` renders `Layout.Header`, an inner `Layout` holds `DesignPanel` (`Layout.Sider`), `BedPanel` (`Layout.Content`) and `MachinePanel` (`Layout.Sider`), and `StatusStrip` renders `Layout.Footer`. The top bar (`$top-bar-height`, 6rem) and the status strip (`$status-strip-height`, 4.75rem) have fixed heights from `layout.scss` and keep their items on one row (`fixed-height-bar` mixin); the coming-soon groups and readouts are clipped first so the title, the connection pill and the console toggle stay visible. `AppUpdatePrompt` is a compact one-row chip with small antd buttons; its message is cut short with an ellipsis and the full text is the chip title. The siders and the console overlay scroll on their own, the bed fills the content area, and the inner layout scrolls when the window is too short. `html` and `body` are exactly 100dvh with overflow hidden, and the root resets the line height that antd `App` sets back to the browser default. The build puts antd's building blocks (`@ant-design/*`, `@rc-component/*`) into an `antd-base` chunk and antd's components into an `antd` chunk (`codeSplitting` groups in `vite.config.ts`; `antd-base` has the higher priority because a group also takes in the modules its matches import), so each stays under the 500 kB warning limit; the PWA precaches both. Sider widths are `DESIGN_PANEL_WIDTH` / `MACHINE_PANEL_WIDTH` (`var(--design-panel-width)` / `var(--machine-panel-width)`), custom properties that `AppRoute` sets from `src/styles/layout.scss` (the console overlay also uses the machine panel width to stop short of it). From 1280 px (`WIDE_LAYOUT_MEDIA_QUERY`, `useIsWideLayout`) the inner layout gets `hasSider` and the panels sit side by side; narrower the widths become `auto` and the regions stack and scroll inside the inner layout. In a wide window the console overlay starts at the design panel's right edge and stops short of the machine panel, so it covers only the bed's lower part and STOP stays visible. `AppRoute` calls `useIsWideLayout()` once and passes `isWide` to `MachinePanel`, so one media-query subscription decides both STOP placements: exactly one STOP is rendered (`StopButton`, an antd primary danger button in the large size, 44 px tall): `StopButton` pinned at the bottom of `MachinePanel` when wide, `StickyStopBar` (rendered by `AppRoute` only when not wide) otherwise. `LeavePageGuard` stays in the route and renders nothing; while `selectIsMachineMoving` is true it holds a `beforeunload` listener that calls `preventDefault()` and sets `returnValue`.
- **Machine panel.** `MachinePanel` stacks `Panel` cards: Status (`MachineStateReadout`: state label, work and machine position with 3 decimals, feed, power, dashes while there is no report; and `MachineResetUnlock`: Reset needs a connection, Unlock also needs Alarm), then the live Move card (`MoveCard`: Home, Set zero, jog pad, steps, jog speed) and Laser pointer card (`LaserCard`: power, hold to fire, air assist; its Frame job button is still `ComingSoon`), both described in [[machine-control]], then `ComingSoon` cards Pre-flight check and Job (Start job). Everything inside a `ComingSoon` block is inert and dispatches nothing (handlers are `doNothing`). `TopBar` has a "Machine profiles" button that opens `MachineProfilesDialog`.
- **Stop hotkey.** `StopHotkey` (rendered by `AppRoute`, renders nothing) listens for `keydown` on `window` in the capture phase and dispatches `MachineStopRequested` on a fresh Escape press (not `event.repeat`, not `isComposing`) only when `selectIsConnected` is true and `selectIsAnyOverlayOpen` is false. It reads the store at key-press time, so it never acts on stale overlay state; antd overlays close on Escape from a bubble-phase `window` listener, so the hotkey always sees them still registered (see [[ui-components]]).
- **antd theme.** `main.tsx` wraps the app in `ConfigProvider theme={ANTD_THEME}` and antd `App`. `ANTD_THEME` (`src/utils/theme/antd.theme.ts`) uses `theme.darkAlgorithm` with our tokens (accent, surfaces, border, text, status colours, radius 8, Inter, control height 36), paints the `Layout` header, siders and footer with our surfaces instead of antd's navy, and sets `Button`, `Switch` and `Segmented` component tokens (details in [[ui-components]]). `antd.theme.test.ts` checks every value against `src/styles/tokens.scss` through `getScssTokenValue`. Our own styling stays in SCSS modules; antd injects its styles at the start of `<head>` with zero-specificity selectors, so a region's CSS-module class overrides antd's base rules (for example the header's fixed 72 px height).
- **Bed.** `BedPanel` (the central region) holds a `ComingSoon` toolbar (antd tool buttons and an antd `Segmented` for Design / Toolpath / 3D), `BedView` and `ToastStack`. `getBedDimensions(settings, isConnected, activeProfile?)` takes the size from the active machine profile's work area when it has a valid one (no placeholder, connected or not; see [[machine-control]]), otherwise from `$130` / `$131` (X / Y max travel, mm); each must be finite, above 0 and at most 5000 mm (`BED_MAX_TRAVEL_MM`), else a 400 mm square default is drawn with a placeholder: `no-machine` while disconnected, `size-unknown` when connected without usable settings. `BedView` (pure SVG, user unit mm, Y axis up) draws the grid (10 mm minor, 50 mm major), rulers, the work-zero marker (`workCoordinateOffset`) and the laser-head crosshair (`machinePosition`). `getBedMarker` clamps a position (the head or the work zero) to the bed and flags `isOutsideBed`, so a head or work zero outside the bed stays visible at the edge in a dashed outside style and the aria label says so. `getRulerLabelPositions(lengthMm, labelClearanceMm)` skips a ruler label whose text would reach past the far edge (top labels need the offset plus their widest text, left labels the offset plus one line), so no label is clipped. `BedPanel` passes its element (`hostRef`) to `AppRoute`, which shares it through `BedRegionHostContext` as the host that `BedRegionModal` and `BedRegionDrawer` render into (see [[ui-components]]).
- **Design panel.** `DesignPanel` holds `ComingSoon` Layers, Objects and Material panels, each with a one-line description of what will appear.
- **Status strip.** `StatusStrip` shows `ComingSoon` readouts (cursor, job size, estimate) and a Console switch (an antd `Switch` in a label, collapsed by default). Open, it renders `ConsolePanel` in a 14 rem overlay anchored above the strip (z-index 30), drawn over the bed without resizing it.
- **Toasts.** `ToastStack` is mounted inside `BedPanel` and anchored to the top right of the bed area (z-index 40, above the console overlay); the stack ignores pointer events except on the toasts themselves. Below 1280 px (`isWide` false, passed down from `AppRoute` through `BedPanel`) the stack gets `pinnedToWindow`: `position: fixed` just below the top bar, so it stays visible while the stacked regions scroll. Its `max-height` (`100dvh` minus the top bar, `$sticky-stop-bar-height` and the gaps, from `src/styles/layout.scss`) means it never overlaps the sticky STOP bar; extra toasts scroll inside the stack (`overflow-y: auto`).
- **Browser environment state.** `browserEnvironment` tracks `isOnline` (fed by a saga listening to `online`/`offline` events) and `isWebSerialSupported` (`'serial' in navigator`). `ConnectionPill` shows both.
- **PWA.** `vite-plugin-pwa` in `generateSW` mode precaches all built assets. `registerType: 'prompt'` means a new version is never activated automatically; `AppUpdatePrompt` asks the user. In tests, `vitest.setup.ts` mocks `virtual:pwa-register/react` and installs a silent `ResizeObserver` for antd.
- **Strings.** Every visible string comes from `t(DEFAULT.<KEY>)`; see [[localization]].
- **Types.** `tsconfig.json` loads `vite/client`, `vite-plugin-pwa/react`, and `w3c-web-serial` (types for `navigator.serial`).
