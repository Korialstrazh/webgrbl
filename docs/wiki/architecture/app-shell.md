# App Shell

The scaffold every feature builds on: entry point, Redux store with sagas, PWA service worker, and the top-level route.

## Key Takeaways

- **CRUV layout.** `src/containers` (components with logic), `src/routes` (one-off top-level pages), `src/utils` (infrastructure), `src/views` (pure presentational components that are not antd: `Panel`, `ComingSoon`, `BedView`, `ConsoleEntryList`). Controls are antd components used directly in containers; see [[ui-components]].
- **Redux with class actions.** Every action is a class extending `Action<TPayload>`; `classActionToPlainObjectMiddleware` runs first and turns instances into plain objects. Each state file holds its state, actions, reducer, sagas, and curried selectors in `#region` blocks.
- **GRBL slices.** `grblConnection` (status disconnected / connecting / connected / lost, granted ports, selected port, baud rate, firmware identity, RX buffer size, settings, build info), `machineStatus` (latest resolved status, cleared on disconnect; and whether the app switched air assist on, cleared on Stop, Reset and disconnect), `grblConsole` (entries capped at 2,000, hidden status reports, command history of 100, app-added info and error lines by localisation key) and `toast` (identical open toasts merge into a repeat count; info toasts expire after 5 s). `machineProfile` holds the machine profiles and the active one (see [[machine-control]]). The slices hold only serialisable data.
- **Controller bridge.** `watchGrblController` (`grbl.controller.saga.ts`) owns the single `GrblController` in saga scope and turns requests into controller calls and controller events into actions and toasts; details in [[grbl-engine]] (Redux bridge). `newStore(dependencies?)` takes optional `GrblControllerSagaDependencies` for tests (simulated laser, in-memory storage) and defaults to the browser's, which work without Web Serial.
- **Connection UI.** `ConnectionPill` (top bar, the one place that tells the connection state: Status card and laser chip hide while disconnected) shows a status dot and label (success connected, warning connecting, danger lost, muted disconnected), the firmware name and version when connected, the active profile, the selected port label, a "No Web Serial" indicator and, while not connected or lost and the Job card is not on screen (narrow layout outside the Job region), "Connect" in the accent colour, so Connect is never offered in more than two places at once (the Job card's readiness step and next-step button cover the other cases); the port reads "No port chosen" until the user picks one, since no port, not even the simulated laser, is preselected; its `aria-label` reads "Connection: <state, firmware, profile, port>. Open the connection menu." Below 62.5 rem it keeps the dot and the Connect verb while disconnected, or the state and the chevron once connected (the machine name stays on the top bar's laser button, shortened, and in the pill's accessible name), so it fits an 800 px bar. The browser's network state is not in the pill (the status strip shows Offline while there is no network). With a port chosen the Connect verb leaves the pill for a joined sibling button that dispatches `ConnectRequested` through `useConnectLaser` (the Job card's Connect step and next-step button use the same hook; with no port it opens the popover instead). The pill button is the anchor (child) of `ConnectionPopover`, an antd `Popover` with `trigger="click"` and `placement="bottomRight"` whose `open` / `onOpenChange` follow `selectIsConnectionPopoverOpen` in the `uiOverlay` slice (`ConnectionPopoverOpenChanged`), so the Status card's Connect button opens the same popover: a click on the pill toggles it, a click outside or Escape closes it. The popover registers itself with `useOverlayRegistration(CONNECTION_POPOVER_OVERLAY_ID, isOpen)`, so Escape never reaches STOP while it is open, moves focus to its first enabled control once open, returns focus to the pill (through `anchorRef`) when it closes with focus inside, and destroys its content while hidden (`destroyOnHidden`). The popover has the port select (an antd `Select`: localized "Simulated laser (no hardware)" plus granted ports, with a "No port chosen" placeholder, as `USB <vid>:<pid>` in 4-digit lowercase hex, "Serial port" when the ids are unknown), a "+ USB" button in the same row as the port select (accessible name "Choose a USB port"), the baud select (an antd `Select`) and the Connect/Disconnect toggle (plug and unplug icons; the port and baud labels carry USB and gauge icons) (disabled while connecting, and Connect also while no port is chosen). Without Web Serial only "Choose port" is disabled and the popover shows the unsupported explanation; the simulated laser stays connectable. Port and baud selects are locked while connecting or connected.
- **Console UI.** `ConsolePanel` owns the input (Enter submits trimmed non-empty text; ArrowUp/ArrowDown walk `commandHistory` newest first, ArrowDown past the newest clears; disabled unless connected), the status-reports checkbox and the auto-scroll: the list follows new lines unless a scroll event left it more than 1 rem (converted through the root font size) above the bottom. `ConsoleEntryList` (view) renders entries with a `>`/`<` prefix, a time, a class per direction, `t()` for info/error lines (`messageKey` + `messageParameters`) and the `CONSOLE_REALTIME_<COMMAND>` label for realtime entries.
- **Route composition.** `AppRoute` is a five-region workbench: `TopBar` (title, project name button and Project menu, Import SVG, undo/redo and the autosave readout, Machine profiles, `AppUpdatePrompt`, `ConnectionPill`; see [[projects-and-svg-import]]), `DesignPanel`, `BedPanel`, `MachinePanel` and `StatusStrip`. The workbench is an antd `Layout` that fills the window (`height: 100dvh; overflow: hidden`, so the page never scrolls): `TopBar` renders `Layout.Header`, an inner `Layout` holds `DesignPanel` (`Layout.Sider`), `BedPanel` (`Layout.Content`) and `MachinePanel` (`Layout.Sider`), and `StatusStrip` renders `Layout.Footer`. The top bar (`$top-bar-height`, 3.5rem) and the status strip (`$status-strip-height`, 3rem) have fixed heights from `layout.scss` and keep their items on one row (`fixed-height-bar` mixin); the readouts are clipped first so the title, the connection pill and the console toggle stay visible. `AppUpdatePrompt` is a compact one-row chip with small antd buttons; its message is cut short with an ellipsis and the full text is the chip title. The siders and the console panel scroll on their own, the bed fills the content area, and the inner layout scrolls when the window is too short. `html` and `body` are exactly 100dvh with overflow hidden, and the root resets the line height that antd `App` sets back to the browser default. The build puts antd's building blocks (`@ant-design/*` into `antd-base`, `@rc-component/*` into `antd-rc`) and antd's components into an `antd` chunk (`codeSplitting` groups in `vite.config.ts`; priorities run `antd-base`, `antd-rc`, `antd` because a group also takes in the modules its matches import), so each stays under the 500 kB warning limit; the PWA precaches all three. Sider widths are `DESIGN_PANEL_WIDTH` / `MACHINE_PANEL_WIDTH` (`var(--design-panel-width)` / `var(--machine-panel-width)`): `100%` in a wide window, where each sider fills its splitter column, and `auto` in a narrow one. From 1280 px (`WIDE_LAYOUT_MEDIA_QUERY`, `useIsWideLayout`) the three panels sit in `PanelSplitter` (`src/routes/AppRoute/PanelSplitter/`), an antd horizontal `Splitter` with one `Splitter.Panel` per region; narrower there is no splitter and the regions stack and scroll inside the inner layout (crossing the breakpoint remounts the panels). The panels open with the stored percentages or, with none stored, the side panels at 20.5 rem and 22 rem (from `layout.constants.ts`, matching `layout.scss`) and the bed taking the rest (`getPanelDefaultSizes`); from 1600 px the defaults start at 24 rem and 22 rem and grow in proportion to the window width, up to the maximum, and are read again on every window resize while nothing is stored (so a window widened after opening grows them too); a stored side panel share that would break its limits on this screen opens at the limit and the bed takes the difference; minimum widths are 16.25 / 30 / 20 rem and the side panels have a 32 rem maximum (`*_MAX_WIDTH_REM`, also passed to the splitter as `max`), converted with `getRootFontSizePixels`. `onResizeEnd` turns the pixel sizes into percentages (`getPanelSizePercents`) and dispatches `PanelSizesResized`; `panel.layout.saga.ts` stores them through `PANEL_SIZES_REPOSITORY` (`appState` key `panelSizes`) and reads them at start (`PanelSizesLoaded`, `panel.layout.state.ts`), together with the console height; a read that neither resolves nor rejects within `PANEL_SIZES_READ_TIMEOUT_MS` (1,500 ms, `race` with `delay`) loads the defaults, so the panels always appear. `getValidPanelSizePercents` rejects a stored value with the wrong count, a number that is not finite or not above 0, or a sum more than 1 from 100, and the defaults apply; storage errors are logged (`logPanelSizesStorageError`). `AppRoute` renders the splitter only once `selectIsPanelLayoutLoaded` is true, so the workbench never jumps from the defaults to the stored sizes. The console is a panel below the bed: in a wide window the middle splitter panel holds `BedColumnSplitter` (`src/routes/AppRoute/BedColumnSplitter/`), a vertical antd `Splitter` with the bed (minimum 22 rem) and, while `selectIsConsoleOpen` is true, `ConsoleDock` (minimum 11.5 rem, so the header, three log lines and the input stay whole; the log itself keeps `min-height: 3lh`). The console height is a controlled size (antd reads default sizes only at mount, and a remount would remount the bed): the dragged height while dragging, else the stored `consoleSizePercent`, else 30 %; `onResizeEnd` dispatches `ConsoleSizeResized`, stored under `appState` key `consolePanelSize` (`getValidConsoleSizePercent`: finite, above 0, below 100). In a narrow window the regions stack with the bed first, then the open console, the design panel and the machine panel, so the first screen shows the work. `AppRoute` calls `useIsWideLayout()` once and passes `isWide` to `MachinePanel`, so one media-query subscription decides both STOP placements: exactly one STOP is rendered (`StopButton`, an antd primary danger button in the large size, 44 px tall): `StopButton` in the footer of `MachinePanel` when wide, `StickyStopBar` (rendered by `AppRoute` only when not wide) otherwise. `LeavePageGuard` stays in the route and renders nothing; while `selectIsMachineMoving` is true it holds a `beforeunload` listener that calls `preventDefault()` and sets `returnValue`. (Final fix wave: below 46rem the top bar keeps only the Import SVG icon and the autosave status icon (labels stay for screen readers; the status icon has a tooltip and an `aria-label`); below 62.5rem the app title is visually hidden and the project name wraps to at most two lines in a 7.5-10 rem heading, so it no longer draws over the Project menu at 684 px. The Status card Connect is a default button; `Panel` headers wrap their action under the title instead of cutting it.)
- **Machine panel.** `MachinePanel` stacks `Panel` cards with the main task first. `MachineStatusCard`: while not connected its heading line only, with "Not connected" after a grey dot and a slim primary "Connect" button that opens the connection popover of the pill; once connected `MachineStateReadout` (the state as a text badge with a dot in the state colour, work and machine position with 3 decimals, feed, power, dashes while there is no report) and `MachineResetUnlock` (Reset needs a connection, Unlock also needs Alarm). Then the live Job card (`JobCard`: layer count, time estimate, Export G-code as the full-width primary action, then Start job, which runs the job after a confirmation, with progress and Pause or Resume during the run (see [[running-jobs]]), and `FrameControls`: grid cell, margin, time and dot power, then the full-width Frame job button, off with the reason in its tooltip or an alert naming the bed edge; see [[running-jobs]] and [[layers-and-gcode]]), the live Move card (`MoveCard`: while not connected one heading line with "Connect to move" and a Show / Hide text button (`aria-expanded`, `aria-controls`) that opens the disabled controls; otherwise `MoveControls`: Home, Set zero, jog pad, steps, jog speed, centred as one column) and Laser pointer card (`LaserCard`: while not connected one heading line, "Connect to use" with the same Show / Hide toggle, both through `CollapsedCardToggle` in `src/views/`; otherwise power, hold to fire, air assist), both described in [[machine-control]]. Disconnected, the cards fit a 1368 x 703 window without scrolling. The move row and Reset/Unlock are capped at the jog pad width (`$machine-control-max-width`, 14.5 rem). The pre-flight check is planned (see [[ui-layout]]) and has no card. Every control inside a `ComingSoon` block is a disabled antd control. The cards scroll in their own area; when content is cut off (`useIsScrollContentCutOff`, `isScrollContentCutOff`) the area's last 2 rem fade out with a mask, and in a wide window STOP sits in a footer below them, never over a card. `TopBar` has a "Machine profiles" button that opens `MachineProfilesDialog`.
- **Stop hotkey.** `StopHotkey` (rendered by `AppRoute`, renders nothing) listens for `keydown` on `window` in the capture phase and dispatches `MachineStopRequested` on a fresh Escape press (not `event.repeat`, not `isComposing`) only when `selectIsConnected` is true and either `selectIsAnyOverlayOpen` is false or `selectIsEscStoppingWithOverlayOpen` is true. That app preference (`appPreferences` slice, default off, loaded and stored by `watchAppPreferences` through `ESC_STOP_PREFERENCE_REPOSITORY` in the `appState` row `escStopsWithOverlayOpen`) is set from the gear (`StopSettingsButton`) beside STOP, in the wide stop footer and the narrow sticky bar; with it on, one Escape closes the overlay and stops. It reads the store at key-press time, so it never acts on stale overlay state; antd overlays close on Escape from a bubble-phase `window` listener, so the hotkey always sees them still registered (see [[ui-components]]).
- **antd theme.** `main.tsx` wraps the app in `ConfigProvider theme={ANTD_THEME}` and antd `App`. `ANTD_THEME` (`src/utils/theme/antd.theme.ts`) uses `theme.darkAlgorithm` with our tokens (accent, surfaces, border, text, status colours, radius 8, Inter, control height 36), paints the `Layout` header, siders and footer with our surfaces instead of antd's navy, and sets `Button`, `Switch` and `Segmented` component tokens (details in [[ui-components]]). `antd.theme.test.ts` checks every value against `src/styles/tokens.scss` through `getScssTokenValue`. Our own styling stays in SCSS modules; antd injects its styles at the start of `<head>` with zero-specificity selectors, so a region's CSS-module class overrides antd's base rules (for example the header's fixed 72 px height).
- **Bed.** `BedPanel` (the central region) holds a toolbar with no tool switch: a click selects and a drag moves (the unbuilt tools are `ComingSoon`; the antd `Segmented` Design / Toolpath / 3D is live, see [[layers-and-gcode]] and [[burn-preview]]; the view mode is the `bedView` slice, `selectBedViewMode`, and in 3D the left panel shows `CutCheckPanel` above Layers with Objects hidden, while STOP stays visible), `BedViewport` (zoom and pan, below) around `BedView` with `BedObjects` drawn over it (select, drag, handles, SVG file drop through `useSvgFileDrop`) and `ToastStack`. `getBedDimensions(settings, isConnected, activeProfile?)` takes the size from the active machine profile's work area when it has a valid one (no placeholder, connected or not; see [[machine-control]]), otherwise from `$130` / `$131` (X / Y max travel, mm); each must be finite, above 0 and at most 5000 mm (`BED_MAX_TRAVEL_MM`), else a 400 mm square default is drawn with a placeholder: `no-machine` while disconnected, `size-unknown` when connected without usable settings. `BedView` (pure SVG, user unit mm, Y axis up) draws the grid (10 mm minor, 50 mm major), the work-zero marker and the laser-head marker (a red crosshair with a ring over a dark halo, so it stays visible over artwork and at the bed corner), both in work coordinates mapped by `getBedPointFromWorkPosition`: the G-code burns relative to work zero, and without homing the machine position's zero is wherever the machine was turned on, so work zero always sits at the origin corner of the drawing. `getBedMarker` clamps a position (the head or the work zero) to the bed and flags `isOutsideBed`, so a head or work zero outside the bed stays visible at the edge in a dashed outside style and the aria label says so. **Zoom and pan.** `BedViewport` (`src/containers/BedViewport/`) holds a session-only `BedViewport` (zoom against the fitted bed, view centre in bed SVG mm; `newFitBedViewport` at start and on Fit; a new bed size remounts it). While a left `BedRegionDrawer` is open on a wide window (`BED_REGION_DRAWER_STORE`, read with `useIsBedRegionDrawerOpen`), `useBedViewportControls` shows `newTopFitBedViewport` (the whole bed fitted at the top of the strip it pushes aside, right under the ruler, or in the whole region under a drawer that overlays it, see [[ui-components]]); the first zoom or pan starts from it, and the viewport from before the drawer comes back once it closes. The zoom is the SVG `viewBox` (`getBedViewBox`, shaped like the view, so a zoomed bed fills it), so `BedObjects` keeps reading pointer positions through the screen matrix (`getBedSvgPoint`) and handles follow the view box (`useBedPixelsPerMm` also watches the `viewBox` attribute). `getZoomedBedViewport` keeps the bed point under the anchor (pointer or view centre) fixed, `getPannedBedViewport` moves with the pointer, and `getClampedBedViewport` keeps the zoom within `MIN_BED_ZOOM` 0.5 to `MAX_BED_ZOOM` 40 and the view centre on the bed. Input: the wheel around the pointer (`getBedWheelZoomFactor`; in a narrow window only with Ctrl or Cmd, so the page scroll is not trapped), a middle drag or Space plus a left drag (`useBedPanGesture`, caught in the capture phase so selecting and dragging objects keep their left drag; Space counts only over the bed and when no text field, overlay or focused control has taken it), or a plain left drag on empty bed (`getBedPressPanStart`: a press outside any `[data-bed-object]` element, which `BedObjectGraphic` carries for the object and its handles, pans once it passes `DRAG_START_DISTANCE_PX`; the press still reaches `BedObjects`, so it clears a selection as before and a double-click can move the laser, see [[machine-control]]); the drawing area shows a grab cursor (grabbing while panning, objects keep their own) and no text selection, `BedZoomControls` (antd buttons with aria-labels and `@ant-design/icons`: bed colour, zoom out, the zoom in %, zoom in, Fit), which `BedViewport` renders through a portal into a slot in the bed header beside the view switch (`controlsHost`), so nothing floats over the drawing and Fit uses the whole bed box, and the keys `+` / `=`, `-`, `0` (`useBedZoomHotkeys`, the guards of the other shortcuts). Markers divide their size by the zoom (`BedZoomContext`, also read by `ToolpathLayer`). The rulers sit in bands of their own (`BedRulers`, laid out by `getBedRulers`): a 1.25 rem band along the top (bed X) and the left (machine Y, labels turned to run upwards), each with a dark chrome background, long ticks at the labelled steps and short ticks at a fifth of a step (left out when closer than 0.375 rem), and a corner square naming the unit. The drawing area starts where the bands end, so labels never sit on the grid or artwork and the first X and Y labels never meet; it takes the pointer and is what `useBedScreenSize` measures. Labels use a fixed `0.75rem` font at the smallest step from `BED_RULER_STEPS_MM` that keeps them 3 rem apart, and a label whose text would pass the bed or its band is left out (its long tick stays). On pointer move `getBedCursorPoint` (machine mm, undefined off the bed) goes to `BED_CURSOR_STORE`, which the status strip reads. `BedPanel` passes its `bedBody` element, everything below the bed header (`hostRef`), to `AppRoute`, which shares it through `BedRegionHostContext` as the host that `BedRegionModal` and `BedRegionDrawer` render into (see [[ui-components]]). (Final fix wave: Edit nodes, Align and 3D moved from the header into `BedMoreToolsMenu`, a More dropdown at the end of the view tools, so the Design header is one row at 1368 px; 3D was later added as a third switch option. Fit leaves `BED_FIT_MARGIN_PX` around the bed, the wheel step is `BED_WHEEL_ZOOM_PER_PIXEL` 0.0006, and the readout shows "100 % (fit)" at the fitted zoom.)
- **Design panel.** `DesignPanel` holds, in the Design view, a Material panel with `ProjectMaterialSelect`, the live Layers panel (`LayersSection`, `AddTestSampleButton` in the Design view once the bed has objects (an empty bed offers it on `BedEmptyCard`, which in the wide layout leaves Import SVG to the Job card's next-step button), the Palette button and `PaletteDialog`, `LayerSettingsDrawer`; see [[layers-and-gcode]]), the live Objects panel, `ObjectsSection` (object list, transform fields, import button; see [[projects-and-svg-import]]).
- **Status strip.** `StatusStrip` shows the job size (`selectReadyToolpathBounds`, `getJobSizeReadoutText`), the estimate and the Cursor readout (`BedCursorReadout`, last so its reserved width leaves no gap: the bed point under the pointer in machine mm with one decimal, a dash otherwise; it reads `BED_CURSOR_STORE` through `useBedCursorPoint`, a `useSyncExternalStore` store outside redux that hands a new point on at most once per animation frame), and a Console toggle (an icon button with `aria-pressed`, off by default) that dispatches `ConsoleOpenChanged`; the workbench lays out the console panel, as a bottom sheet over the region on screen in a narrow window. `ConsolePanel` shows a hint while its log is empty. (Final fix wave: each readout is `white-space: nowrap` and never shrinks; below 46rem the Cursor readout hides so the strip stays one row. While the toolpath is generating, job size and estimate show "Calculating..."; the toolpath saga regenerates an idle or stale toolpath in the background after document or machine-area changes, so the values show in the Design view. The job size tooltip says it is the burnt area plus overscan, unlike the object's "Frame" size.)
- **Coming soon, focus and splitters.** `ComingSoon` wraps one control, which the caller renders with antd `disabled` and the wrapper shows as a ghost (no fill, a dashed outline, muted text), and puts one small neutral "Soon" tag (`SoonTag`) right after it; the description is in an antd `Tooltip` below the control, on the wrapper because a disabled button fires no pointer events (hover, or focus of the tag), and in hidden text for screen readers. Only real controls get one; placeholder-only cards and menus stay off the screen. The muted text token `--color-text-muted` (`#b0b6bd`) passes 4.5:1 on the background, the bed and every surface (`tokens.contrast.test.ts`). Disabled controls share one look: `--color-disabled-bg`, `--color-disabled-text` (5.3:1) and a border fainter than the enabled one (`--color-disabled-border`, antd `colorBorderDisabled` / Button `borderColorDisabled`); disconnected STOP is a neutral default button (no `danger`) with a muted label and icon. Outlined and text danger buttons use `--color-danger-text` (global rule in `global.styles.scss`), and the selected antd `Menu` row is the main text on surface-3 (`Menu` tokens) with an accent edge. antd 6 renders the splitter dragger without a tab stop or key handling, so `SplitterHandles` (`src/views/SplitterHandles/`) lays a focusable `role="separator"` handle over each bar with its name and the bar position and range in percent; the arrow keys step the controlled sizes by 1 rem and Home / End go to the ends of the range, stored like a drag. One focus ring for every control: a global `:focus-visible` rule in `global.styles.scss` and antd's `colorPrimaryBorder` / `lineWidthFocus` tokens, both the accent (`--color-focus-ring`, 3:1 on every surface). Splitter bars use the `Splitter` component tokens: a border-coloured line and a muted 2 rem grip at rest, the accent on hover and drag.
- **Toasts.** `ToastStack` is mounted inside `BedPanel` but `position: fixed`. From 1280 px (`isWide`) it docks in the free right part of the status strip, right of the readouts (`$status-strip-readouts-width`) and left of the console toggle (`$status-strip-toggle-width`), up to 40 rem wide so a usual message stays on one line; it never covers the job size, estimate or cursor readouts, the bed drawing or STOP (z-index 40, above the console overlay). Below 1280 px the stack gets `aboveStopBar`: right-aligned just above the status strip and the sticky STOP bar, up to 24 rem wide, where a drawing placed from the bed origin is least likely to be. Every toast stretches to the widest one, so a stack lines up as one column; the stack ignores pointer events except on the toasts themselves, its `max-height` keeps it below the top bar, and extra toasts grow upward and scroll inside it (`overflow-y: auto`). Dialogs dim the app with a 65 % mask (`colorBgMask`) and lift off it with a deep shadow (`Modal.boxShadow`).
- **Browser environment state.** `browserEnvironment` tracks `isOnline` (fed by a saga listening to `online`/`offline` events) and `isWebSerialSupported` (`'serial' in navigator`). The status strip shows an Offline note while `isOnline` is false; `ConnectionPill` shows the Web Serial note.
- **PWA.** `vite-plugin-pwa` in `generateSW` mode precaches all built assets. `registerType: 'prompt'` means a new version is never activated automatically; `AppUpdatePrompt` asks the user. In tests, `vitest.setup.ts` mocks `virtual:pwa-register/react` and installs a silent `ResizeObserver` for antd.
- **Strings.** Every visible string comes from `t(DEFAULT.<KEY>)`; see [[localization]].
- **Types.** `tsconfig.json` loads `vite/client`, `vite-plugin-pwa/react`, and `w3c-web-serial` (types for `navigator.serial`).
