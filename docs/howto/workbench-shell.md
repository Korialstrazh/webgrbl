# Workbench shell

The app is one screen, the Workbench, made of five regions plus overlays. This page shows which container owns what and how to add a feature. Design details: `docs/wiki/architecture/app-shell.md` and `docs/wiki/architecture/ui-components.md`.

## Regions

`AppRoute` (`src/routes/AppRoute/`) composes the regions. From 1280 px they sit side by side (antd flex Layout); narrower they stack.

From 1280 px the design panel, the bed and the machine panel sit in an antd `Splitter` (`src/routes/AppRoute/PanelSplitter/`): the user drags the bars between them to resize them. The top bar and the status strip are not part of it.

The splitter sizes are controlled percentages, so the bars also work from the keyboard. antd's own drag bars cannot take the focus, so `SplitterHandles` (`src/views/SplitterHandles/`) lays one focusable `role="separator"` handle over each bar ("Resize the design panel", "Resize the machine panel", "Resize the console") with `aria-orientation` and the bar position, minimum and maximum in percent (`aria-valuenow`, `aria-valuemin`, `aria-valuemax`, from `getSplitterBarRange`). The arrow keys along the bar direction move it one `SPLITTER_KEYBOARD_STEP_REM` (1 rem), Home and End move it to the ends of its range (`getSplitterKeyTargetPercent`, `getMovedSplitterSizes` in `src/utils/layout/`), and the new sizes are stored like a drag (`PanelSizesResized`, `ConsoleSizeResized`). The handles let the pointer through to the antd bars; the grip shows on hover over a bar and on focus of a handle with the shared focus ring.

- Defaults: the design panel 20.5 rem (328 px, wide enough for a layer name such as "Shading (black)" on one line), the machine panel 22 rem, the bed takes the rest (`DESIGN_PANEL_DEFAULT_WIDTH_REM`, `MACHINE_PANEL_DEFAULT_WIDTH_REM` in `src/utils/layout.constants.ts`, matching `layout.scss`).
- Minimum widths: design 16.25 rem, bed 30 rem, machine 20 rem (`*_MIN_WIDTH_REM`); maximum widths: design and machine 28 rem (`*_MAX_WIDTH_REM`), so a wide screen gives its extra width to the bed. All are turned into pixels with the root font size, so they follow the user's font size.
- Stored sizes open as stored, except that a side panel whose share would break its minimum or maximum on this screen opens at that limit and the bed takes the difference (`getPanelDefaultSizes`). The limits also hold while dragging.
- When a drag ends, the sizes are stored as percentages of the workbench width in IndexedDB (table `appState`, key `panelSizes`, `PANEL_SIZES_REPOSITORY`), through `PanelSizesResized` and `panel.layout.saga.ts`. They are not stored on every move.
- At start the saga reads them (`PanelSizesLoaded`); the wide workbench waits for that read, so it opens with the stored sizes instead of jumping from the defaults. If the read neither resolves nor rejects within `PANEL_SIZES_READ_TIMEOUT_MS` (1,500 ms, a `race` with `delay`), the defaults apply, so the panels always appear. A stored value with the wrong count, a number that is not finite or not above 0, or a sum more than 1 away from 100 is ignored, and the defaults apply. A failed read or write is logged and the defaults or the current sizes stay.
- In a wide window the console is a panel, not an overlay. The Console toggle button (`aria-pressed`) in the status strip dispatches `ConsoleOpenChanged` (`selectIsConsoleOpen`, not stored). In a wide window the middle column is a vertical `Splitter` (`src/routes/AppRoute/BedColumnSplitter/`): the bed on top (minimum 22 rem, `BED_PANEL_MIN_HEIGHT_REM`) and, while open, the console below it (`ConsoleDock`, minimum 11.5 rem, `CONSOLE_PANEL_MIN_HEIGHT_REM`: the header, three log lines and the input). Its height is a controlled percentage of the column, default 30 % (`CONSOLE_PANEL_DEFAULT_SIZE_PERCENT`); a drag end stores it through `ConsoleSizeResized` (`appState` key `consolePanelSize`). The bed panel stays mounted while the console opens and closes. In a narrow window one region shows at a time, and the open console is a bottom sheet over it (`ConsoleDock`, absolute inside the regions box, at least 40 % of the window (16 rem at the least) and at most 60 % of the regions box tall, `$console-sheet-height`; a log line scrolled half out at the top fades into the edge instead of showing cut off; headed by the same terminal icon as its toggle), so Stop in the sticky bar stays free. While the sheet is open the region on screen ends where it begins (`narrowRegionsWithSheet`, `$console-sheet-height`), so the bed re-fits to the space above it and re-fits back when it closes. Choosing another region in `NarrowRegionBar` closes the sheet, and so does a bed drawer (`BedRegionDrawer`) when it opens, so the two never stack; the sheet can be opened again over the drawer. The narrow sheet does count as an overlay (`useConsoleSheetEscape` in `ConsoleDock` registers it while it is open in a narrow window): the first Escape closes it and does not stop, unless **Esc stops over panels too** is on. It reads whether it is the top overlay in the capture phase and closes in the bubble phase, so Escape over a dialog or popover on the sheet closes only that. The docked wide console is no overlay, so there Escape keeps its Stop meaning. The expand icon in the console header opens the log in a large dialog (`ConsoleLogDialog`, 64 rem wide, its log 60 % of the window tall so it ends above STOP) with the same lines and the same command input (`ConsoleCommandInput`).
- Below 1280 px there is no splitter: the regions stack as before. Crossing the breakpoint mounts the panels again.

## Add a feature to a region

Every unbuilt control is wrapped, one control at a time, in `ComingSoon` (`src/views/ComingSoon/`): the control itself is a real antd control with `disabled`, shown as plain muted text and icon with no fill and no outline, so with its tag it reads as a note and never as a working control, and a small neutral "Soon" tag (`SoonTag`, `src/views/SoonTag/`) sits right after it. The description shows in a tooltip below the control (so it never covers the top bar) on hover over the wrapper, because a disabled button fires no pointer events, or when the tag takes the keyboard focus. Unbuilt bed tools and views (Edit nodes, Align, 3D) are not shown one by one but listed in the bed header's More menu (`BED_COMING_SOON_TOOLS`), so the header stays one row. Never leave an enabled-looking control that does nothing on click, and never put two controls under one tag. Only real controls get a Soon tag: a Soon control is never a solid primary button, and a card, panel or menu that would hold nothing but a placeholder is left off the screen and listed as planned in `docs/wiki/product/ui-layout.md`. Keep the main screen at about four Soon tags. To build one:

1. Replace the `ComingSoon` block with your real component in the owning container (or a new child container next to it).
2. Put state and dispatching in a container; keep pure drawing in `src/views/`. Build controls from antd (`Button`, `Switch`, `Checkbox`, `Input`, `Segmented`, `Popover`, and selects and sliders as needed; dialogs and drawers only through `AppModal`, `BedRegionModal` or `BedRegionDrawer`) with prop values from `src/utils/antd.constants.ts`; do not write new self-built buttons or toggles. Machine controls use `size={ANTD_BUTTON_SIZE_LARGE}` (44 px), icon-only buttons need an `aria-label`, and a `Switch` sits in a `<label>` with visible text. Every form field shows a short visible name: number fields pass `captionText` to `IconNumberField` (Width, Depth, Thickness, Speed, Passes, Max, Min), and text fields put `InputCaption` (icon plus one word, such as Name) in their `prefix` instead of relying on a placeholder.
3. A control inside `ComingSoon` is `disabled` and has no handler. Once it is real, remove the wrapper and the `disabled`.
4. Add strings to the localization CSV (see `docs/howto/localization.md`) and use `t(DEFAULT.<KEY>)`.

## Bed zoom and pan

`BedViewport` (`src/containers/BedViewport/`) wraps `BedView` and owns the session-only viewport (`BedViewport` in `src/utils/bed/interfaces/`: zoom against the fitted bed and the view centre in bed SVG mm). It starts fitted and starts over when the bed size changes (`BedPanel` keys it by the bed size). `BedPanel` keeps the latest viewport in a `KeptBedViewportRef` and passes it as `keptViewportRef`, so leaving for the 3D view (which unmounts the viewport) and coming back keeps the zoom and pan; opening the console only changes the screen size, so a zoomed view keeps its zoom and a fitted one re-fits. A new bed size empties the kept viewport.

- Mouse wheel: zooms around the pointer, gently (`BED_WHEEL_ZOOM_PER_PIXEL` 0.0006: 6 to 15 % per notch) in a wide window; in a narrow window, where the page scrolls, only Ctrl or Cmd plus the wheel zooms (`useBedWheelZoom`).
- Pan: drag with the middle mouse button, or hold Space over the bed or Ctrl (Cmd) and drag (`useBedPanGesture`, `getBedPressPanStart`); these presses are caught in the capture phase and never reach the objects, even on top of one. A left drag on empty bed, or on an object while nothing is selected, pans too once past the drag distance; such a press on an object picks it only on release (`BedObjects` keeps it pending), so a click still selects. Only a selected object moves under a plain left drag.
- Buttons and keys: the cluster in the bed header beside the view switch (`BedZoomControls`: bed colour, zoom out, the zoom in %, zoom in, Fit; `BedViewport` renders it through a portal into the header slot, so nothing floats over the drawing and Fit uses the whole bed box) and the keys `+` / `=`, `-` and `0` (`useBedZoomHotkeys`, same guards as the other app shortcuts).
- Fit and the zoom label (the readout is a plain percent; the Fit button shows as pressed while the view is fitted, and at phone width the readout is hidden so the group fits): Fit leaves `BED_FIT_MARGIN_PX` (16 px) free on each side of the bed. The zoom is relative to the fitted bed; a tooltip on the readout explains it. It is not a real 1:1 scale.
- Limits and steps: `MIN_BED_ZOOM` 0.5, `MAX_BED_ZOOM` 40, `BED_ZOOM_STEP_FACTOR` 1.25 (`src/utils/bed/bed.zoom.constants.ts`).

The zoom is the SVG `viewBox` (`getBedViewBox`, shaped like the view so a zoomed bed fills it), so every pointer position read through the SVG's screen matrix (`getBedSvgPoint` in `BedObjects`) is already in bed mm; new pointer code must read positions the same way, or through `getBedViewPoint` from the viewport, never from raw pixels. Markers divide their size by the zoom (`BedZoomContext`), handles follow the view box through `useBedPixelsPerMm`. The rulers sit in bands of their own (`BedRulers`, `getBedRulers`): a 1.25 rem band along the top (bed X) and the left (machine Y, its labels turned to run upwards), each with its own background, long ticks at the labelled steps and short ticks at a fifth of a step, and a corner square that names the unit. The drawing area starts where the bands end (`$bed-ruler-band-size` in `layout.scss`), so no label sits on the grid or the artwork and the first X and Y labels never meet; it is the element that takes the pointer and that `useBedScreenSize` measures, so pointer positions stay in bed mm. The labels keep a fixed `0.6875rem` font and a step that keeps them 3 rem apart. The status strip's Cursor readout reads the bed point through `BED_CURSOR_STORE`, which hands it on at most once per animation frame, outside redux.

## Overlays and Escape

- Never use a raw antd `Modal` or `Drawer`. Pick the wrapper by size:
  - **Editing dialogs** (palette, machine profiles, open project, add material) use `AppModal` (`src/containers/AppModal/`): rendered into the page body with a mask over the whole window, centred, `width: min(maxWidth, 100vw - 2rem)` (`getAppModalWidth`), and the body scrolls inside the window height, so the form and the close button are never cut off. STOP stays above their scrim: the wide stop footer and the narrow sticky bar sit at `$stop-above-dialog-z-index` (`src/styles/layout.scss`, above antd's highest nested dialog layer, 2000), and in a narrow window the dialog centres in the space above the sticky bar. Their two-column content stacks below 48 rem.
  - **Small confirmations** use `BedRegionModal` (`src/containers/BedRegionModal/`) and drawers use `BedRegionDrawer` (`src/containers/BedRegionDrawer/`): they render into the bed region below the bed header (the `bedBody` element of `BedPanel`), so they never cover the bed toolbar, with a mask over the bed only, so STOP stays visible and clickable (the drawer mask is clear, so the bed stays in view; a click on it still closes the drawer). From 1600 px a left drawer pushes the bed aside and the whole bed fits beside it; below that it slides over the bed, which keeps its size and zoom and pans right just enough for the selected object to clear the drawer, and pans back when it closes. In a narrow window, Start and the stop settings in the bottom bar are inert while a dialog or drawer is open; STOP stays active. A dialog opened from outside an open bed drawer (the top bar, a hotkey) closes the drawer first (`useCloseOnUnrelatedDialog`), so Escape never reveals a drawer left behind; a dialog opened from inside it, such as Add material or the palette, keeps it open beneath.
  - All three register as open overlays themselves and close on Escape through `onClose`.

```tsx
<AppModal isOpen={isOpen} overlayIdPrefix={MATERIAL_DIALOG_OVERLAY_ID} maxWidth={MATERIAL_DIALOG_WIDTH} title={titleText} onClose={closeDialog}>
  {contentComponent}
</AppModal>
```

- Every container that owns an antd `Popover` must call `useOverlayRegistration(OVERLAY_ID_PREFIX, isOpen)` from `src/utils/hooks/use.overlay.registration.ts`, with the same `isOpen` it passes to the overlay's `open`. The hook adds a unique id (prefix plus `useId()`) to the `uiOverlay` slice while open and removes it on close or unmount.

```tsx
useOverlayRegistration(CONNECTION_POPOVER_OVERLAY_ID, isOpen);

return (
  <Popover open={isOpen} onOpenChange={handleOpenChange} trigger={ANTD_POPOVER_TRIGGER_CLICK} content={contentComponent}>
    {children}
  </Popover>
);
```

- Escape rule: `StopHotkey` stops the machine only when connected **and** no overlay is registered open. antd closes the overlay on Escape after `StopHotkey` (capture phase) has already seen it registered, so one press never does both. A forgotten registration would make Escape stop the machine while the overlay is open. Exception: when the app preference `isEscStoppingWithOverlayOpen` (`appPreferences` slice, stored in the `appState` row `escStopsWithOverlayOpen`, set from the `StopSettingsButton` gear beside STOP, whose popover points at the gear with an arrow and explains the option in one line) is on, `StopHotkey` also stops with an overlay open; antd still closes the overlay on the same press. It defaults to off.
- Popovers over dialogs: `AppModal`, `BedRegionModal` and `BedRegionDrawer` register with `OVERLAY_KIND.DIALOG` (third argument of `useOverlayRegistration`). Each dialog or drawer opening raises `dialogOpenCount` in the `uiOverlay` slice and closes the connection popover there; the frame settings, Stop settings, Project menu, bed colour and connection popovers close through `usePopoverAutoClose`, which also closes them when the narrow layout switches region, so no popover stays open over a dialog or another region. A new popover should call that hook too.
- antd `Popover` moves no focus: move focus into it on open and back to the opener on close, as `ConnectionPopover` does. The dialog and drawer wrappers handle focus themselves: `AppModal` traps focus like any antd modal (STOP sits above its mask and stays clickable; Escape closes the dialog first, a second Escape stops); `BedRegionModal` closes on Escape and returns focus to the opener but does not trap Tab (rc-dialog only locks focus when its wrap is `position: fixed`, and the wrapper makes it absolute), so STOP stays reachable by keyboard; the drawer traps focus while open, and STOP stays clickable with the mouse.
- Tests that open antd overlays render inside `AntdTestProvider` (`src/utils/test.support/antd.test.provider.tsx`), which turns antd motion off for jsdom.

## One STOP

Exactly one STOP is rendered: `StopButton`, an antd `Button` with `size="large"`, and `type="primary"` with `danger` while connected. `AppRoute` calls `useIsWideLayout()` once and passes `isWide` to `MachinePanel`: wide shows `StopButton` in a footer below the panel's scrolling cards (never over them), narrow shows `StickyStopBar` (rendered by `AppRoute`): a filled red STOP, taller (3 rem) and three times as wide as Start, with a 16 px gap before it; Start there is a smaller, outlined secondary button with the same guards and confirmation. Disconnected, STOP is a neutral disabled button (`type="default"`, no `danger`, grey icon, no red), a readable `--color-text-muted` label and an unplugged icon with a short visible "Not connected" cue inside the button (hidden from its name), plus a visually hidden "Laser not connected" description (`aria-describedby`); it turns solid red only when it can act; it shows its Esc shortcut (`aria-keyshortcuts="Escape"`). Do not add further STOP buttons or call the hook elsewhere for this.

## Tokens and fonts

- All colours, radii, spacing, fonts and sizes are CSS custom properties in `src/styles/tokens.scss`; use `var(--...)` only (never raw hex or px). Notable ones: `--color-danger-button` for danger buttons (contrast), `--target-min` (2.75 rem machine-control target), `--control-height`, `--focus-outline-width` / `--focus-outline-offset` with `--color-focus-ring`, `--radius-pill`.
- The bed work surface defaults to a light grey (`DEFAULT_BED_COLOUR`, `--color-bed-surface`, black artwork 9.2:1) while the area around it, the ruler bands and the panel chrome stay dark. Anything drawn on the bed uses the `--color-bed-*` tokens (grid, accent, laser head, danger, travel, ink, text, chip border), never the chrome colours. The grid tokens are mixed from the bed colour itself (darker on a light bed, lighter on a dark one), so the grid keeps the hue of any bed colour.

## Bed colour

The user picks the bed colour from the swatch button at the start of the zoom cluster in the bed header (`BedColourPicker`, an antd `ColorPicker` with named, keyboard-reachable preset buttons Grey (default), Light grey, White, Dark grey and Plywood (`BED_COLOUR_PRESETS`), a note that a very dark bed hides black artwork, and Reset to default). The button is a paint-bucket icon beside a bed-shaped swatch of the current colour with a light edge, so even a dark bed shows on the toolbar; like the zoom buttons beside it, it has no caption, and its tooltip and accessible name are "Bed colour". The Design / Toolpath / 3D captions use the body size in the full text colour. On a dark bed (`data-bed-tone="on-dark"`) the design view draws a light halo around every object (two crisp 1 px white drop shadows and a soft 3 px glow, `BedObjectGraphic` styles; never on the selection box, and an object that runs off the bed is drawn at 55 % opacity without the halo, so a huge off-bed guide never glows across the canvas), so black fills and pure blue strokes stay legible; layer colours, the saved bed colour, the toolpath and the G-code do not change.

- State and storage: `bedAppearance` slice (`BedColourChanged`, `BedColourLoaded`, `selectBedColour`); `bed.appearance.saga.ts` reads `BED_COLOUR_REPOSITORY` at start under the panel sizes read timeout and stores changes app-wide (not per project) in `appState` key `bedColour`, debounced by `BED_COLOUR_STORE_DEBOUNCE_MS`. A missing or invalid stored value (`getValidBedColour`: six-digit hex only) keeps the default.
- Applying it: `BedPanel` sets `--color-bed-surface` inline on the bed area and `data-bed-tone` from `getBedOverlayTone`, which compares the colour's relative luminance (`getColourRelativeLuminance`) with `BED_OVERLAY_TONE_LUMINANCE_THRESHOLD` (0.179, where black and white marks contrast equally). `tokens.scss` defines an `--color-bed-on-light-*` and an `--color-bed-on-dark-*` set; `[data-bed-tone='on-dark']` switches the `--color-bed-*` tokens to the light marks. Each set keeps 4.5:1 for marks and text and 3:1 for markers against the default bed of its side (`tokens.contrast.test.ts`).
- A new mark on the bed must use a `--color-bed-*` token and get a value in both sets.
- New colours must keep 4.5:1 text contrast (`tokens.contrast.test.ts`). The focus ring (`--color-focus-ring`, the accent) must keep 3:1 on every surface; it is the one ring for every control: a global `:focus-visible` rule, and antd's `colorPrimaryBorder` and `lineWidthFocus` tokens. After a pointer press (`FocusRingModality` sets `data-pointer-modality` on the root) no control but a text field draws it, so focus that a closing popover, drawer or dialog hands back never looks selected or in error; Escape keeps that look, any other key brings the ring back. The bed's objects layer shows it as a ring on the bed edge only for keyboard focus; a press on the bed (which also focuses it) leaves the edge plain, so a selection shows on the object's box and handles alone.
- Splitter bars take their colours from the `Splitter` component tokens: a border-coloured line with a muted 2 rem grip at rest, the accent on hover and drag.
- Text and number fields (`Input`, `InputNumber` component tokens) take a grey edge (`--color-control-border`) on hover and the accent only while focused, so two fields never both look active. `IconNumberField` takes `hasTooltip={false}` where its visible caption already names it, as in the Add material dialog, so no tooltip opens over the field above when the dialog opens.
- Icons come from `@ant-design/icons` (outline set, pinned to the version antd resolves) and keep the control's `aria-label`; never use Unicode glyphs (arrows, crosses, carets, playback symbols) as icons. The jog pad turns one `ArrowUpOutlined` with its `rotate` prop (`JOG_ARROW_ROTATION_DEG`).
- Inter and JetBrains Mono are self-hosted in `src/styles/fonts/` (`fonts.scss`); do not load fonts from a CDN, the app works offline.
- antd components get the same look through `ANTD_THEME` (`src/utils/theme/antd.theme.ts`), whose values mirror `tokens.scss` (checked by `antd.theme.test.ts`). A new colour used by antd goes into both files.
- The default panel widths and the top bar (3.5 rem) and status strip (3 rem) heights live in `src/styles/layout.scss`.

## Bed sizing

`getBedDimensions` (`src/utils/bed/`) sizes the bed from the active machine profile (`selectActiveMachineProfile`), or else from GRBL `$130` (X) and `$131` (Y) max travel in mm:

- An active profile with a work area above 0 and at most 5000 mm sets the size, connected or not, with no placeholder.
- Each value must be a finite number above 0 and at most 5000 mm; otherwise a 400 mm square is drawn.
- Disconnected: the 400 mm square with the "no machine" placeholder. Connected without usable `$130`/`$131`: the square with the "size unknown" placeholder.
- `BedView` draws the head crosshair at the machine position and the work zero marker from the work coordinate offset. A head outside the bed is clamped to the nearest edge and the aria label says it is outside the bed.

## Icon notes

A short note shown as an info (or other) icon in a tinted circle (`TooltipNoteIcon`) opens its text in a popover on hover, on a tap or click, and on Enter or Space, so no note depends on hover alone.

Palette rows show their Move up, Move down and Delete buttons only on the row being edited, the hovered row or the row holding the focus; they stay in the tab order. The Shading row marks itself built-in with a small certificate badge (its name shows on hover and is read out); the note that the palette order is not the cut order lives in the Help popover. In a narrow window the Bed segment of the region bar uses the bed outline icon (`BorderOuterOutlined`), as the profile's Bed group does.

## Bed pan by dragging

A left drag on empty bed pans the view, with or without a selection; a press on an object or handle still selects and moves it. `getBedPressPanStart` (`src/containers/BedViewport/`) decides: middle press or Space plus left press pan at once, a left press outside `[data-bed-object]` (`BED_OBJECT_SELECTOR`) pans after `DRAG_START_DISTANCE_PX`, anything else never pans. Mark any new draggable bed element with `data-bed-object`, or a drag on it will pan the bed. The empty-bed press is not stopped, so `BedObjects` still clears the selection on it and gets its double-click.



The view switch marks the current view with a bold white caption on the accent tint, an accent icon and an accent bar along its bottom edge; the other views have muted captions. Every antd `Segmented` (view switch, narrow region bar, step sizes, toolpath and playback modes, layer mode) passes `tabIndex={SCRIPT_FOCUS_ONLY_TAB_INDEX}`: antd makes the group box focusable as well as the checked option, so without it each switch took two tab stops. `antd.upgrade.guard.segmented.test.tsx` guards that antd keeps taking the prop.

## Toasts

Messages appear at the top centre of the window, above everything including STOP. Each one closes itself after 5 seconds, and its close button (x) removes it sooner. Every toast is also recorded in the message history (`messageHistory` slice, `src/utils/states/message.history.state.ts`; repeats included, newest 200 kept): the bell in the status strip (`MessageHistoryButton`) carries a badge with the number of messages since the history was last opened, and opens `MessageHistoryDialog`, which lists every message newest first with its time, severity icon and full text, and a Clear all button (hidden while the history is empty, when the dialog shows only its bell empty state).

## Tooltips after a view change

`TooltipDismissal` closes hover tooltips on resize, blur, scroll and bed view changes. On a narrow region switch or a tab visibility change it also sets `data-tooltip-hold` on the root element (`holdTooltipsUntilPointerMoves`), which hides every `.ant-tooltip` until the pointer moves at least 4 px, so a control that appears under a resting pointer does not open its tooltip.

## antd components only

Build UI from antd. ESLint (`webgrbl/no-raw-form-elements` in `eslint.config.mts`) rejects raw `<button>`, `<input>`, `<select>` and `<textarea>` in `src/**/*.tsx` outside tests. When antd has no fit (the hidden file pickers opened from an antd `Button`), disable that line with a comment saying why. Restyle antd parts from the component's CSS module with `.myClass:global(.ant-...)` selectors; `Panel` (antd `Card`) is the base of every workbench card.
