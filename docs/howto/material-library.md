# Material library

Presets hold the power, speed and passes that work for a material on one machine. The design is in `docs/superpowers/specs/2026-11-04_(01)_material-library.spec.md`.

- **Where things live:** model and file handling in `src/utils/materials/`, state in `src/utils/states/material.preset.*`, UI in `src/containers/MaterialLibraryDrawer/`. The entry point is `MaterialSection` in the Material panel of the Design view (a Library button, and a preset summary link that passes `initialMaterialId`, count from `selectActiveMaterialPresetCount` over `getMaterialPresetCount`); the layer drawer's `LayerPresetButtons` opens the same drawer with `initialLayerKey`. The material select's option detail uses `getMaterialPresetCount` too, so the count and the burn test state are named apart.
- **Drawer and layout:** `MaterialLibraryDrawer` renders a `BedRegionDrawer` (left, `min(68rem, 100%)`), owns the export ticks for the `PresetFileActions` in the drawer header, and wraps the editor in a `container-type: inline-size` body; the editor's SCSS puts the panes side by side above 60rem of drawer width and stacks them below, with the drawer body as the one scroll container. `BedRegionDrawer` sets `push={false}`, so the library opened from the layer drawer does not push it aside.
- **Editor state:** `MaterialLibraryEditor` owns the draft the form edits, compares it with the stored preset (`isSameMaterialPreset`) to decide whether Save or Apply is the main action, keeps the material filter (`materialId` in `getMaterialPresetRows`, shown as a chip by `MaterialLibraryFilters`), and shows one confirmation line (`role="status"`) under the edit pane's actions that clears itself through `useExpiringValue` (`INLINE_FEEDBACK_LIFETIME_MS`). `MaterialPresetTable` renders the rows, with the percent of `activeProfile` beside the watts (`getPresetPowerPercent`); with `rowApply` set (opened from a layer) each row of the active machine gets a labelled Apply button and shows an Applied tag (`appliedPresetId`) for a moment after a click. `useApplyPresetToLayer` is the one place that applies a preset to a layer, used by the edit pane and the row buttons.
- **Duplicates from a layer:** `getMatchingMaterialPreset` finds the stored preset of the same material, operation and machine; `LayerPresetButtons` then asks Update existing, Save as new or Cancel in a Popover rendered into its own button row. Updating keeps the id and the notes of the stored preset.
- **Storage:** the `materialPresets` Dexie table. Only `MATERIAL_PRESET_REPOSITORY` touches it, and `watchMaterialPresets` keeps it in step with the state.
- **Add a field to a preset:** change `MaterialPreset`, `isMaterialPreset` and the form. Stored rows without the field are left out by the guard, so give old rows a Dexie upgrade. Also update the file format, and raise `MATERIAL_PRESETS_FILE_VERSION` if old files can no longer be read.
- **Power:** always stored in watts. Convert with `getPresetPowerPercent` (for display and `getPresetLayerSettingsChange`, to a layer) and `newMaterialPresetFromLayer` (from a layer). `getImportedMaterialPresets` rescales a file for the importing laser.
