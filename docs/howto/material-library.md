# Material library

Presets hold the power, speed and passes that work for a material on one machine. The design is in `docs/superpowers/specs/2026-11-04_(01)_material-library.spec.md`.

- **Where things live:** model and file handling in `src/utils/materials/`, state in `src/utils/states/material.preset.*`, UI in `src/containers/MaterialLibraryDrawer/`. The entry point is `MaterialSection` in the Material panel of the Design view (a Library button, and a small preset button with an icon and its label (a list icon with the count, a plus with "Add preset" when there are none, the laser icon with "Laser profile" when no profile is active) that passes `initialMaterialId`, count from `selectActiveMaterialPresetCount` over `getMaterialPresetCount`); the layer drawer's `LayerPresetButtons` opens the same drawer with `initialLayerKey`. The material select's option detail uses `getMaterialPresetCount` too, so the count and the burn test state are named apart.
- **Drawer and layout:** `MaterialLibraryDrawer` renders a `BedRegionDrawer` (left, `min(27rem, 100%)`, one narrow column), owns the export ticks for the `PresetFileActions` in the drawer header, and wraps the editor in a body of the full height. `MaterialLibraryEditor` shows one view at a time: the list view (`MaterialLibraryFilters` and `MaterialPresetTable`) while no draft is open, the edit view (`MaterialPresetForm`, the feedback line and `PresetLayerApply`) once a row is opened or a preset added. Each view is a flex column; the list scroller or the form's `.fields` is the one part that scrolls, so the toolbar, Back, Save, Delete and the apply block stay in view. `BedRegionDrawer` sets `push={false}`, so the library opened from the layer drawer does not push it aside.
- **Editor state:** `MaterialLibraryEditor` owns the draft the form edits, compares it with the stored preset (`isSameMaterialPreset`) to enable Save, keeps the material filter (`materialId` in `getMaterialPresetRows`, shown as a chip by `MaterialLibraryFilters`, which also shows the "Layer: ..." chip when opened for a layer), and shows one confirmation line (`role="status"`) under the actions that clears itself through `useExpiringValue` (`INLINE_FEEDBACK_LIFETIME_MS`). `MaterialPresetTable` renders each preset as a two-line row (name, then the numbers with the percent of `activeProfile` beside the watts through `getPresetPowerPercent`, and the machine name when the filter is off); with `rowApply` set (opened from a layer) each row of the active machine gets a labelled Apply button and shows an Applied tag (`appliedPresetId`) for a moment after a click. `PresetLayerApply` is always rendered in the edit view with `preset` undefined while nothing can be applied, and says why. `useApplyPresetToLayer` is the one place that applies a preset to a layer, used by the edit view and the row buttons.
- **New material inside the library:** `MaterialDialog` takes an optional `onMaterialChosen(materialId)`; with it, Save and "Use that one" hand the id to the caller instead of dispatching `ProjectMaterialSelected` (the Material panel and the burn preview pass nothing and keep selecting for the project). The editor hosts one dialog for its three entries (the New material button, the empty state, and the `NEW_MATERIAL_OPTION_VALUE` entry of the form's material select): with a draft open the id goes into the draft, otherwise into the material filter. A newly saved material also becomes the project material while the project has none: selecting one changes only `document.materialId`, never a layer value or the G-code. "Use that one" does not do this, and the "Filter: ..." chip (dashed, with a filter icon) only narrows the list.
- **Duplicates from a layer:** `getMatchingMaterialPreset` finds the stored preset of the same material, operation and machine; `LayerPresetButtons` then asks Update existing, Save as new or Cancel in a Popover rendered into its own button row. Updating keeps the id and the notes of the stored preset.
- **Storage:** the `materialPresets` Dexie table. Only `MATERIAL_PRESET_REPOSITORY` touches it, and `watchMaterialPresets` keeps it in step with the state.
- **Add a field to a preset:** change `MaterialPreset`, `isMaterialPreset` and the form. Stored rows without the field are left out by the guard, so give old rows a Dexie upgrade. Also update the file format, and raise `MATERIAL_PRESETS_FILE_VERSION` if old files can no longer be read.
- **Power:** always stored in watts. Convert with `getPresetPowerPercent` (for display and `getPresetLayerSettingsChange`, to a layer) and `newMaterialPresetFromLayer` (from a layer). `getImportedMaterialPresets` rescales a file for the importing laser.
